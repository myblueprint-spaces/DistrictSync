# Configuration reference

Developer reference for the district mapping YAML (`config/mappings/`): the eight field-mapping types, the `global_config` knobs that scope and filter what ships (`excluded_course_codes`, `class_rostering_grades`, `student_rostering_grades`, `row_filters`, `cross_enrollment`), the bundled-config roster, and `district_domains` with the unknown-key rule. Moved **verbatim** from `CLAUDE.md`'s **Configuration-Driven Design** section by plan 0053 S15 (2026-09-30) — headings and paragraph breaks added; the changes inside it are listed in `.claude/plans/0053-s15-disposition-map.md`. The step-by-step procedure for adding a district, and the frozen self-service overlay shape, are in [adding-district.md](adding-district.md); the rules stay in `CLAUDE.md` (**Configuration-Driven Design**). Two of the bundled-config count sentences live in this guide and are parity-pinned by `tests/test_config_count_pin.py` beside `tests/_pins.py` — a new config bumps them ([adding-district.md](adding-district.md), Step 5).

## Field-mapping types

All field mappings are in YAML files under `config/mappings/`. The `--sis` CLI argument selects which mapping file to load (e.g., `myedbc` -> `myedbc_mapping.yaml`). Mappings support:
- Direct column mappings (string value)
- Transform functions (dict with `transform` key, e.g., `grade_to_ceds`, `map_role`, `normalize_staff_role`). Only `ALLOWED_TRANSFORMS` in `base.py` are permitted. **Two role transforms, deliberately distinct:** `map_role` reads a teaching FLAG (`Y` → teacher, **everything else** → NO role — blank and `nan` included; it can no longer return `administrator`, plan 0052, and `tests/test_role_mapping.py` pins that as a RULE over arbitrary input rather than a value table), while `normalize_staff_role` reads a column that STATES the role and **RAISES** on any other value (per-row blank + data error, never a guessed role). `STAFF_ROLES` in `base.py` is the single source for the two-value output vocabulary.
- Fixed values (dict with `value` key)
- Academic year dates (dict with `use_academic_year` key). **Every live config auto-derives** (`use_academic_year: true`); the `use_academic_year: false` + `value: "YYYY-MM-DD"` escape hatch is supported but currently **unused** — the pins were removed district-wide by `506d63d` (2026-06-04) once end-year school-year semantics were fixed. The frozen SD74 snapshot config (`tests/snapshots/config/`) still pins dates **deliberately**, to keep the golden time-independent — do not "sync" it to the live config.
- ID year-appending (dict with `append_year_to_id` key)
- Email format templates (dict with `format` key, e.g., `{student number}@sd40.bc.ca`). Opt-in (default off → other districts byte-identical): `sanitize: true` reduces each substituted value to `[a-z0-9]`; `derived_dates: {pseudo: {column, date_format}}` injects a date part (e.g. `yy`) derived from a source date column into the template (reuses base date machinery; empty on blank/unparseable; fail-loud on a missing column). SD60 uses both to generate `{legal first}{legal surname}{admission yy}@learn60.ca`.
- Name config (dict with `primary teacher flag`, `teacher last name`, `course title`, `section letter`)
- ID-role pair (dict with `student_id_col` and `staff_id_col`)
- Headers for headerless files (dict with filename -> column name list)

## `excluded_course_codes`

`global_config.excluded_course_codes` (list[str]) filters schedule + class_info rows by Course Code (case-insensitive, trimmed) before class/enrollment/blended generation. SD40 uses `["ATT--AM", "ATT--PM"]` to drop MyEd BC's internal attendance-only sections. Applied in `base.filter_excluded_course_codes()` and called from `classes.py`, `enrollments.py`, and `blended.py` (the schedule-fallback path).

## Grade scopes: `class_rostering_grades`

`global_config.class_rostering_grades` (opt-in, plan 0042 1a; `Literal["homeroom"] | list[str] | None`, default `None` ⇒ today's behaviour byte-identical) is the **COMPLETE** set of grades that get class rostering, in **CEDS OUTPUT space** (`KG`/`01`… — never raw `"K"`/`"3"`; valid set = `grades.CEDS_GRADE_CODES`, derived from `CEDS_MAPPING.values()`, and `"Other"` is its one mixed-case member so nothing may case-normalise the codes). `homeroom_grades ⊆ class_rostering_grades` is VALIDATED, which is *why* the homeroom path needs no change: homeroom scope = `homeroom_grades`, timetable scope = the difference, grades in neither get NOTHING. `"homeroom"` is sugar for "rostered == homeroom_grades" (empty timetable scope) — SD83's shape, the only shipped consumer, `version: '1.10'` (quoted: PyYAML collapses bare `1.10` → `1.1`). Four boundary rules fire only when the key is set (`GlobalConfig.check_rostering_grade_scopes` + the `mode="before"` shape validator): CEDS shape · non-empty list · subset · **`homeroom_grades` itself CEDS-validated** (under the sentinel it *becomes* the rostered set, so nothing else would check it; general `homeroom_grades` validation stays a roadmap gap). The scope is derived by ONE function, `grades.resolve_timetable_scope`, called at each of its three consumers (`classes.py`/`enrollments.py`/`blended.py` — pure, so they cannot disagree) (`None` = no scope in force — branch on `is None`, NEVER truthiness: an empty set means "roster no timetable classes") and applied INSIDE `split_by_homeroom_grades(keep="subject")`, the one place the grade→CEDS conversion happens — because `grade_to_ceds` is **not idempotent** (`KG`/`IT`/`PR`/`PK`/`PS` are values, not keys, so a second pass yields `"UG"`). `keep="homeroom"` + `timetable_scope` **RAISES** (an ignored filter argument is the banned permissive default). `blended._register_blends` drops a blend none of whose grades receives subject rostering — **before any `result.*` write**, since `class_map`/`teacher_map` are written before the grade range is known and a later `continue` would leave orphan Class IDs in `Enrollments.csv` (the `e187ac8` partner-ingest rejection).

**UNGATED since plan 0043 (2026-08-14):** the gate masks on `grades.timetable_rostered_grades(homeroom_grades, timetable_scope=…)` — the configured scope when there is one, else `CEDS − homeroom` — so it fires for EVERY district, and it reads PER-ROW pupil grades (`_build_enrollable_grade_map`, **no `dropna`**, derived via `grades.ceds_grade_series`) rather than `_build_grade_map`'s per-section MODE. That row-set identity with `split_by_homeroom_grades(keep="subject")` is an INVARIANT, not a detail: a `dropna`-built map misses blank grades (which become `"UG"`, are timetable-side and are REAL students), suppressing a blend that has a pupil, re-keying them to a per-section class and GROWING `Classes.csv`. `validate`/`get_grade_range` keep the MODE map, so blend qualification and NAMES are unchanged — hence a survivor can be named for grades none of its pupils holds (accepted; ROADMAP). Still necessary-not-sufficient: a blend whose in-scope pupils are all inactive still ships studentless.

## Grade scopes: `student_rostering_grades` (and the config-format minor)

`global_config.student_rostering_grades` (opt-in, plan 0042 1b; `list[str] | None`, default `None` ⇒ every grade, byte-identical; shipped consumers since 2026-08-31: `sd27myedbc`/`sd38myedbc`, the phase-2 8-12 scopes) is the **OUTERMOST** bound: the complete set of grades whose STUDENTS reach the output at all, same CEDS OUTPUT space. It ANDs with the active-status filter (neither replaces the other) and narrows Family/Classes/Enrollments/StudentCourses through the existing `active_student_ids` roster — no per-entity wiring (`StudentAttendance` sits OUTSIDE that cascade — pre-existing, ROADMAP). Validated chain `homeroom_grades ⊆ class_rostering_grades ⊆ student_rostering_grades`, each link checked when both sides are configured (with the class key absent, `homeroom ⊆ student` is checked DIRECTLY — transitivity gives nothing); `[]` is REJECTED (it can only end at the delivery floor) while `homeroom_grades: []` stays legal; and it is REJECTED on a config whose `enabled_entities` omits `Students` (`MappingConfig.check_student_scope_requires_the_students_entity`) — otherwise the key is silently inert, since only `StudentTransformer` publishes the roster and `filter_to_active` fails safe on an empty one.

**The inherited bound:** with `class_rostering_grades` ABSENT the timetable scope becomes `student − homeroom` — so the blend-suppression gate must branch on the RESOLVED scope (`timetable_scope is not None`), NEVER on the class key's presence, which is silently dead on exactly this path (`docs/INVARIANTS.md`). Applied by `students.py` between the cross-enrollment collapse and `apply_field_map`, via `grades.filter_to_grade_scope` (derive a temp CEDS column → mask → DROP it → copy; no `keep=` argument, so it cannot rewrite in place — an in-place rewrite would hit the field_map's second `grade_to_ceds` and ship every Kindergarten student as `Grade = "UG"`). Grade column via `columns.resolve_source_column`, **RAISING** when unresolvable (fail-open would deliver unlicensed students' PII); log is counts-only.

`SUPPORTED_CONFIG_MINOR` is **15**, and the declared range stays converged with it: sd27/sd38 declare quoted `version: '1.11'` (2026-08-31), sd83 quoted `'1.12'` (2026-09-14, Staff `row_filters` + `normalize_staff_role`), sd51myedbc quoted `'1.13'` (2026-09-16, the `blended_classes` opt-out), sd45myedbc quoted `'1.14'` (2026-09-30, `class_id_year`, released in v3.26.0) and sd40myedbc quoted `'1.15'` (plan 0053 S10, built as 1.14 and moved up when v3.26.0 released 1.14 first: the Classes-only `session_components` declaration — its schedule has no Term column, so it declares the three blended time-slot roles it has, keeping its key byte-identical while §5 #39 stays strict on the effective set) — each shipped WITH its only consumer, so no lag; the loader prose + `TestDeclaredRangeVersusSupported` move with each bump.

## The bundled configs

`sd83myedbc` (K̓wsaltktnéws ne Secwepemcúl’ecw, formerly North Okanagan-Shuswap) is an 8th, also `_base: myedbc`, but opts into the full myBlueprint+ tier (all 7 entities) with district-specific overrides: `homeroom_grades` extended through 08, `class_rostering_grades: "homeroom"` (K-8 classes only; 9-12 stay ROSTERED so their transcripts work), `course_start_grade: 9`, and Date of Birth withheld (`{value: ""}`). **Since 2026-09-14 it is also the ONLY consumer of Staff `row_filters` + `normalize_staff_role`** (`version: '1.12'`): its export repurposes MyEd BC's `Prefix` courtesy-title column to STATE the role, so `Role` reads `Prefix` and the entity drops rows whose `Prefix` is not a role. Employment status is NOT filtered here — `filter_departed_staff` already covers every district and fails OPEN, which a fail-CLOSED `row_filters` entry would not. `tests/test_contract.py` gives it its own `_create_sd83_inputs`. Standard MyEd BC file naming.

3 myBlueprint+ tier configs — `mbp_all` (all 7), `mbp_core` (Students + CourseInfo + StudentCourses), and `mbponly` (CourseInfo + StudentCourses only) — also `_base: myedbc`, overriding `enabled_entities`.

## `district_domains`, picker scoping and unknown keys

`district_domains` (top-level, beside `district_name`) is the district's PUBLIC staff email domain list — PRESENTATION metadata. **Read since S4a** by `mapping_catalog.district_domain_index` → the launch page + the Settings identity section, and since S4b the Home ask + mismatch cards (which build the index LAZILY, on Save only — never on mount; the not-listed card is domain-free, matching an SD number against `available_configs()`).

**The PICKERS ARE SCOPED since S5** via `mapping_catalog.filtered_catalog` (wizard District step + its auto-select seed · Settings folders card · Convert · Mapping), and **UNCONDITIONALLY since 2026-08-04** — the per-surface "Show all districts" row and its `components.list_scope_row` factory, the `show_all` parameter and `FilteredCatalog.can_filter` are all DELETED (owner decision; do not re-add a widening control). Scoping is visibility, never access: the filter still fails OPEN everywhere (no identity / no match / unreadable catalog / any raise → the full list), the saved + picked districts still ride every list, **and since 2026-09-03 so does every `origin == "user"` row unconditionally** (owner finding: a matched admin could not see the mapping they authored themselves — a widening by ONE structural fact, NOT the retired per-surface toggle; see DECISIONS), and the remaining escape for a BUNDLED row is blanking the stored address in Settings. Structurally invisible to the ETL (`to_raw_dict` emits only `mappings` + `global_config`).

**Picker ORDER is decided once, in `mapping_catalog._PINNED_FIRST`/`_pinned_order`** (QA 2026-08-18: `myedbc` leads — alphabetical order buried the generic mapping behind the three `mbp_*` tiers). It is a PERMUTATION (never adds or drops a row) and deliberately NOT in `available_configs()`, whose alphabetical order the CLI/`make validate-config`/the pinned 21-config count depend on. Sixteen shipped rows: sd10/27/38/40/45/48/51/54/60/67/69/71/74/75/83 at `sd##.bc.ca` — SD45 also at `wvschools.ca`, SD60 at `prn.bc.ca`, SD75 at `mpsd.ca` — plus Unity Christian at `unitychristian.ca` (STAFF domains, deliberately NOT generated student domains); base + `mbp_*` carry none (unclaimed = shown in every UNMATCHED state — filter tier (ii) carries no unclaimed row unless it is the saved or picked district); `sd51attendance` INHERITS SD51's via `_base`.

A field validator rejects anything that isn't a lowercase domain — a pasted email address fails `make validate-config` LOUDLY.

`MappingConfig` declares `extra="ignore"` explicitly (forward-compat: a root key from a newer build must not fail a district's sync); the leaf models that forbid extras are `EmailDerivedDate`, `RowFilter`, `CrossEnrollmentConfig` and, since plan 0053 S12, EVERY field-mapping variant (`ConfiguredField` + subclasses — a `transfrom:` typo is refused for every origin, naming the nearest key); `GlobalConfig`/`EntityConfig` stay `ignore` at the Pydantic level because an unknown key there (or an unknown `source_columns` role — the vocabulary is each transformer's `SOURCE_COLUMN_ROLES`) is judged by ORIGIN in `loader.unknown_config_keys`: a BUNDLED config raises `UnknownConfigKeyError` at load, a USER-dir overlay WARNS one line per key and runs, authoring (`validate_overlay`) refuses — so a typo'd `enabled_entities` is no longer silently dropped. Both directions pinned by `tests/test_config_district_domains.py` + `tests/test_config_unknown_keys.py`.

**No `version:` bump for a presentation key** — the loader's bump-MINOR convention is scoped to ETL-affecting keys (2026-07-29 decision).

## `row_filters` and `cross_enrollment`

An entity may declare `row_filters` (list of `{column, include: [...]}`) to keep only matching rows before mapping — AND-combined, fails loudly if the column is missing (a typed `SourceSchemaError` at the ENTITY's declared scope since plan 0053 S4: a Family filter leaves only Family out, a Staff filter still fails the run — `outcomes.ENTITY_CRITICALITY`). Implemented on **Family and Staff only** (the generic helper is `base.apply_row_filters`; widening it further is a ROADMAP item, NOT a config change — the key is silently inert on every other entity): SD60's Family keeps only `Parent Auth / Guardian = Y` rows, SD83's Staff keeps only stated-role `Prefix` rows. **It is NOT the employment-status hook** — `StaffTransformer.filter_departed_staff` owns that, data-keyed for every district and fail-OPEN, where `row_filters` fails CLOSED (a missing column raises); do not re-express one as the other. **Staff's call site is AFTER `_merge_roster`, and that ordering is load-bearing** — the merge REPLACES `working` with a frame rebuilt from `context.raw_data`, so filtering at transform entry (where Family's sits) is silently undone on any district with a roster file (DECISIONS 2026-09-14; pinned). `global_config.cross_enrollment.{collapse, home_school_column}` is an opt-in dedupe that collapses a student's duplicate cross-school rows to their home-school row while preserving enrollments/classes at every school the student attends (off unless a district config sets `collapse: true`).
