Developer reference for the pipeline's moving parts beyond [architecture.md](architecture.md)'s overview: the extractor, every entity transformer, the loader's backup-and-restore commit and output-folder pre-flight, config loading and the quality report; the **Key Data Flow** narrative per entity (Students, Staff, Classes, Enrollments, StudentAttendance), the run record, `PipelineResult`, the full exit-code contract and field-transform failures; and the notes on the run-store, SFTP-uploader and column-name modules. The rules — the zero-orphan invariant, the exit-code contract, the staff role rule, the dry-run store gate, the `.copy()` rule and anomaly detection — stay in `CLAUDE.md` (**Key Data Flow**); the failure policy is [failure-policy.md](failure-policy.md), the output contract [output-contract.md](output-contract.md), and the config keys [configuration-reference.md](configuration-reference.md).

## Pipeline subsystems

### Extractor (`src/etl/extractor.py`)
Loads GDE files with multi-encoding fallback (UTF-8 -> Latin1 -> CP1252) and auto-delimiter detection (comma/tab). Supports headerless files via `file_headers` parameter (column names injected from YAML config). Normalizes column names (lowercase + strip) immediately after loading.

### Transformer (`src/etl/transformers/`)
Entity-specific transformers using Strategy Pattern with a registry:

- `base.py` — Abstract `BaseTransformer` with shared utilities (grade mapping, school year determination, academic date calculation, `assign_class_ids()` shared by Classes+Enrollments). Has `ALLOWED_TRANSFORMS` allowlist for security.
- `context.py` — `TransformContext` dataclass for cross-entity shared state
- `registry.py` — Maps entity names ("Students", "Staff", etc.) to transformer classes
- `students.py` — Active student filtering (enrollment status + withdrawal date with 4 date formats), CEDS grade mapping, email generation
- `staff.py` — Staff records; departed-staff exclusion + the role rule. **A teaching flag NEVER produces `administrator`** (plan 0052): `map_role` yields `teacher` for `Y` and `NO_STAFF_ROLE` otherwise, and `resolve_staff_roles` (post-field-map, so it sees the RESOLVED Role from either transform) RESCUES unroled rows whose person is teacher-of-record on a section, then DROPS the rest
- `family.py` — Parent/guardian contact extraction
- `classes.py` — Homeroom generation + subject classes + blended class integration
- `enrollments.py` — Student + teacher enrollment rows from schedule data; `.copy()` before mutations
- `blended.py` — Blended class detection (same teacher/time with 2+ grade levels -> merged class), minus any blend none of whose pupils would be subject-rostered (see `class_rostering_grades` in [configuration-reference.md](configuration-reference.md)). Falls back to deduplicated schedule when ClassInfo lacks required columns.
- `course_info.py` — (myBlueprint+, opt-in) Course catalog from CourseInformation.txt; pattern-excludes K/early-grade/X/ATT codes; uses `apply_field_map` (config-driven).
- `student_courses.py` — (myBlueprint+, opt-in) Per-student transcript joining course history + selection + info; retake/in-progress/passed dedup; config-driven source columns since W4b1 (field_map + optional `source_columns:` block).

### Loader (`src/etl/loader.py`)
Writes DataFrames to CSV (UTF-8 with BOM) with field ordering from YAML config. `save_all()` uses atomic transactional writes: stages to `.tmp_<timestamp>/`, commits all on success, rolls back on failure.

`save_all` commit is **backup-and-restore atomic** (`_commit_staged`): each existing target is moved into `.bak_<ts>/` then the staged file promoted with `os.replace` (atomic same-fs overwrite, not `shutil.move` — fixes the Windows copy2+unlink within-file tear); any mid-commit failure rolls back (restore originals / remove new files) so the output dir is **never left torn**. Rollback runs inside the `except` and re-raises *before* the `finally` rmtrees `.bak_<ts>/` (restore-before-cleanup invariant).

**Output-folder pre-flight (0050).** `loader.output_target_problem(path)` (`None` = usable, else a log-only reason) runs at both entry points **before any ETL work**, skipped when `dry_run`. GOTCHA: in `convert_job` it sits right after the blank-output guard, **NOT at that function's own `DataLoader` line**, which is *after* the whole ETL. The write additionally catches **`OSError` only** → `RunErrorCategory.OUTPUT` / `ConvertStatus.OUTPUT_FOLDER_UNUSABLE`. Rationale + the fail-loud reversal: `docs/DECISIONS.md` (2026-09-17).

### Config (`src/config/`)
- `models.py` — Pydantic v2 models for YAML mapping validation. 8 field mapping types detected by `classify_field()`: direct mapping, transform, fixed value, academic year, append year, email format, name config, ID-role pair. EntityConfig also supports `headers` dict for headerless files.
- `loader.py` — YAML loading with `_base` inheritance (deep merge, cycle detection) and Pydantic validation. `load_config(sis_type)` returns a validated `MappingConfig`.

### Quality (`src/quality/report.py`)
`DataQualityReport` checks: missing/empty fields (>50% threshold), duplicates per entity-specific keys, orphaned enrollments (class or user not found), grade distribution anomalies.

## Key Data Flow

- **Students** — Filtered to active via the config-driven predicate in `BaseTransformer` (`is_active_mask`): status ∈ `active_values` (default `["Active", "PreReg"]`, the Advanced CSV spec's expected values; Inactive/etc. excluded, `EnrollStatus.active_values` overrides). Status wins when present; the withdraw date is only a fallback for rows with **no** status value (past/unparseable → Inactive, 4 formats). **AND, opt-in, grade-scoped** — `global_config.student_rostering_grades` narrows the roster to the listed CEDS grades (absent ⇒ every grade; the two filters compose, neither replaces the other). Publishes the active roster to `context.active_student_ids`.
- **Staff** — **No role is ever inferred from the absence of one** (plan 0052; `StaffTransformer.resolve_staff_roles`, AFTER `apply_field_map` because the rule is about the RESOLVED `Role`). A row whose role the export does not state is first RESCUED — published as `teacher` if the person is teacher-of-record in any `TEACHING_ASSIGNMENT_SOURCE_ROLES` file (`student_schedule`/`class_info`/`student_demographic`, the last being the HOMEROOM teacher; `staff_info` is excluded and **that exclusion is load-bearing** — it lists every employee, so admitting it rescues the whole export) — and otherwise DROPPED. Never `administrator`, never a blank `Role`. The rescue is one-directional: a stated `administrator` is always believed. **Deliberately NO empty-output floor**, the inverse of `filter_departed_staff` below: publishing nobody is recoverable, publishing the wrong privilege level is not. The timetable is reached via `context.entity_mappings` (the whole config's `mappings`, published once by `run_transform`) — **not** `context.global_config`, which carries only the `global_config` SECTION and has never held `mappings`, which is why `get_teacher_id_col` (0052) and `get_demo_student_col`/`get_students_config` (0053 S9) read `entity_mappings` FIRST.

  **Departed staff excluded automatically** (`StaffTransformer.filter_departed_staff`), keyed on DATA not per-district config, so a district nobody has looked at is covered: when the resolved status column is present AND its non-blank values are a subset of `KNOWN_STATUS_VALUES` (`{active, inactive}`), only `Active` survives. A BLANK status is DROPPED (2026-09-09 owner decision — a staff record has no withdraw date to fall back on, so a missing status is not a positive signal of employment). **Fails OPEN twice, deliberately:** an UNRECOGNISED vocabulary (`A`/`I`, `Employed`/`Terminated`) and a filter that would keep ZERO rows both WARN and ship every row — shipping a few departed staff is recoverable, delivering an empty `Staff.csv` is not. The `enroll_status` machinery cannot serve here (it is keyed on the *Students* field_map and needs a withdraw date), which is why this rule is narrower and lives in `staff.py`. Column name via the entity's `source_columns.staff_status` (default `column_names.STAFF_STATUS`); log is counts + vocabulary only, never a name. Applied AFTER `_merge_roster` (which REPLACES the working frame) and BEFORE `apply_field_map`.
- **Classes** — Join schedule + course info + staff info + optionally class info (for blended). Homeroom classes auto-generated for configured grades. Class names truncated to 100 chars.
- **Enrollments** — Homeroom + subject + blended teacher enrollments. Deduplicated on Class ID + User ID + Role. Invalid teacher IDs ("nan", blank) filtered out. **Zero-orphan invariant:** student rows (homeroom + subject) + homeroom-class creation are filtered to `context.active_student_ids` via `BaseTransformer.filter_to_active`, so no enrollment/class references a student absent from `Students.csv`; teacher rows are not roster-filtered — but a staff member or class LEFT OUT for a missing required value leaves no row (plan 0053 S13d, `failure-policy.md` §5 #42 — `context.left_out_staff_ids`/`left_out_class_ids`; narrow: a teacher absent from `Staff.csv` for another reason stays).
- **StudentAttendance** — union of TWO bands resolved BY `source_files` role (`daily_absences` K-7 derived / `period_absences` 8-12 pass-through), and the union is **NOT naive**: a period row whose `(School Number, Absence Date, Student Number)` the daily band already reported is SUPPRESSED (`suppress_overlapping_period_rows`, pure + total). The bands are two SOURCES, not two FACTS — a district taking attendance in an `ATT--*` section records the same absence twice, and since the CSV carries NO band marker SpacesEDU weighs each row by the pupil's GRADE and ADDS them, turning a half-day into a full day (SD60 2026-09-09: 44 of 73 period rows duplicated, 34 student-days over a full day). DAILY WINS — it carries `Portion Absent` + the AM/PM codes and its category is DERIVED not passed through. Category is deliberately NOT in the identity (`A` vs `AD-E` is still one day off). A period-ONLY student-day is untouched, so genuine 8-12 per-period multiplicity survives intact. Keyed on the student-day, **NEVER** on a course code — `excluded_course_codes` excludes `ATT--*` as not-a-CLASS, but that section is exactly where attendance is TAKEN.
- **Structured logging + run store** — after each run the record is built ONCE → both the `__DISTRICTSYNC_RUN__` diagnostic log line (timing, counts, SFTP status, rich free-text error detail) AND the durable SQLite run store (`src/history/store.py`, bounded `error_category` only — privacy split). The store is the Run History source; the log stays ops diagnostics. Store writes are best-effort/non-fatal and never alter the exit-code contract. **`dry_run` writes NO store record on any path** (success/failure/early-exit — the gate sits at `_store_run_record`, the **pipeline's** single store sink, with `dry_run` required keyword-only so no path can forget it): a preview writes no files, so it must not paint a sync on Home or add a Run History row; its log line is unchanged. Scope: `screens/convert.py` (`_record_manual_run`) calls `write_run_record` directly and so bypasses that gate — Convert has no preview mode, and would need its own gate if one is added
- **`run_pipeline` returns `PipelineResult`** (`entity_counts`, `sftp_attempted`, `sftp_ok`, `anomalies`, `input_columns`, and the REQUIRED kw-only `entity_outcomes` — one `src/etl/outcomes.EntityOutcome` per configured entity, also on every run record as the additive `entity_outcomes` key; plan 0053 S2); a requested SFTP upload that fails logs ERROR (`"SFTP upload FAILED — output files were NOT delivered to <host>"`) and `main` exits code **3** (ETL output still written, not rolled back)
- **Exit codes** — `0` success · `1` ETL/arg/validation error · `2` stdin empty or mutually-exclusive flags · `3` SFTP delivery failed (ETL output present). **No usable required input at all** (every required file missing/empty, checked right after `extractor.load_data`) → exit **1**; since owner decision 2026-09-28 (plan 0053 S13c) **every file a CRITICAL entity lists is required too** — `pipeline.check_required_inputs` (both entry points): missing, or present with no data rows → `IncompleteInputError`/`incomplete_input`, exit **1** (only Family's own file may be missing/empty — and, since plan 0053 S13e (owner ruling 2026-09-30), the Class Information file of a config whose blended detection is off, which leaves only Enrollments' co-teacher rows out with the amber `coteacher_source_unusable` note; ONE predicate, `outcomes.source_file_may_be_absent`, decides both; a `MAY_BE_EMPTY` StudentAttendance file may be row-less, never missing) — and a CRITICAL entity that comes out EMPTY stops the run (`run_transform` → `EmptyRequiredOutputError`/`empty_required_output`, exit **1**; never a header-only CSV). The only run that completes without a configured OUTPUT file is a PARTIAL one without Family — its file missing/empty or its transform FAILED (plan 0053 S4, D3: exit **0**, the record carries it, Home warns); a blended-off night without its Class Information INPUT completes with every output, co-teachers left out (exit **0**, amber — S13e); the old "a partial run with some empty sources stays exit 0" contract is retired. **One exception to "nothing usable" (owner ruling 2026-09-30):** an all-`MAY_BE_EMPTY` (attendance-only) config whose listed files are ALL present but row-less is a success with nothing to send — exit **0**, nothing written/archived/delivered, Home green (`outcomes.nothing_to_send`; `has_no_usable_input(*, configured, absent)` + `check_delivery_integrity(*, outcomes)`).
- **Fail-loud field transforms** — `apply_field_map` is **row-resilient**: a row whose transform raises blanks only **that cell** (valid rows keep their value), an unknown-transform / column-level error blanks **that column**; every failure is recorded to `context.data_errors` → surfaced as the run-log `data_errors` summary (`{total, by_field}`) + Run History "Completed with N data errors". Data errors are a **separate axis** — ETL `status` stays `success` and the run still delivers (never silently swallowed, never fails the run for one bad row).

## The run store, delivery and column names

- `src/history/store.py` — SQLite run store (`history.db` in `paths.user_data_dir()`; replaces the retired `run_log` log-parser). `write_run_record` = sole creator/migrator (schema + `user_version=1`, WAL/DELETE fallback, strictly non-fatal + post-commit, quarantine-recreate on corruption, never downgrades); `read_run_records` never creates the DB (missing/empty→`[]`, error→`None`, else newest-first flat dicts). Written by BOTH `run_pipeline` and `convert_job` (source ∈ manual/scheduled/cli/unknown); the `__DISTRICTSYNC_RUN__` log line stays as diagnostic parity (rich error detail there, bounded `error_category` only in the store). `store_meta().created_at` = fresh-start signal.
- `src/sftp/uploader.py` — `SFTPUploader` with paramiko SSHClient + OS keyring (both top-level imports). Zips all CSVs into `districtsync_YYYY-MM-DD.zip` before upload. Host restricted to `ALLOWED_SFTP_HOSTS` (3 SpacesEDU servers). Credential setup: the Flet Setup SFTP section (`src/ui_flet/screens/setup.py`) **and** headless CLI (`--sftp-configure` / `--sftp-test` / `--sftp-show` in `src/main.py`). Exposes `get_stored_password() -> str | None` (keyring read used by Setup to verify credentials are readable by the current account).
- `src/etl/column_names.py` — Column name constants (avoid magic strings across transformers)
