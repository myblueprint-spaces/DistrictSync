## Problem

Four owner-approved gaps (Brief 0037, Phase 1):

1. **The exe ships ~100MB of Flutter client it doesn't need.** The `full` desktop flavor is embedded on Windows/macOS (`.github/workflows/flet-pack.yml:30,46`) though the app uses no audio/video; Linux already ships `light` (PLAT-0b). D-0037-1 flips Win/mac to `light`. A standing decision (DECISIONS 2026-07-14) declined this pending "a green Win+mac UI smoke"; the pack smoke is the closest existing instrument — it gates offline-embed on all three OSes and window-exists + zero-orphan close on Windows (macOS close is INFO-only), and it asserts no rendered content. **It has never run on `light` for Windows or macOS** — the flip PR's own CI run produces that evidence, and the pre-tag QA-checklist walk on the built exe (required by D-0037-6) is the rendered-content gate. Expected saving: the 2026-07-14 entry measured the full client at 99.8MB and estimated 30–45MB; the size-echo step settles the real number.
2. **The new-user front door is a door into a room you're standing in.** Unconfigured Home renders an onboarding hero whose CTA routes to the Setup rail item (`src/ui_flet/screens/home.py:285-290` → `onboarding.py`). D-0037-2: Home hosts the wizard itself. Post-setup, Home is a metric-tile dashboard (`home.py:207-209`) whose tiles lose their counts on any imperfect run (ROADMAP L59); D-0037-3: slim Home = one verdict line + quick actions.
3. **The app doesn't know who it's talking to.** All 11 district configs are offered to every admin in three pickers; the highest-consequence wrong click in the product is picking the wrong district (a wrong mapping ships a wrong roster — student PII). Two of the eleven rows render byte-identically today ("SD51 - Boundary School District" twice — `sd51attendance_mapping.yaml` inherits SD51's `district_name`; verified). D-0037-4 (as re-revised by the owner 2026-07-28 — flag 3): a launch identity page resolves the admin's work email **by its domain** against per-district `district_domains` lists carried in the bundled YAMLs and scopes every district list; labels become distinguishable.
4. **The output contract lives nowhere.** No doc lists the emitted CSV columns; `tests/test_contract.py:35-57` asserts membership (not order), covers 5 of 8 entities, and asserts nothing about the per-entity BOM rule (`loader.py:53`). Brief item 4: an in-repo `docs/developer/output-contract.md` + strengthened tests.

Plus the P1 leftovers: the Convert header chip asserts the *saved* district while the run uses the *picked* one (`convert.py:1166-1173` — the code comment admits it); no CI job runs the built exe's CLI branch at all (and `flet-verify.yml`'s path filter excludes `config/**`, so config PRs never build an exe); QA-checklist and product-spec rows for every new surface.

## Approach

### Identity = one pure primitives module + one additive config key + one launch page that can never trap anyone

- **Primitives** (`src/utils/identity.py`, COUNTED): `normalize_email` (lowercase/trim; NFC; plus-addressing and trailing-dot handling decided once and pinned) and `extract_domain` (the part after the final `@`, normalized); `validate_identity_email` lives in `validators.py` (allowlist charset, exactly one `@`, ≤254 chars, reject CR/LF/control chars) and runs at the boundary before normalize/persist. **No salt, no hashing, no scheme** — matching compares public organizational facts (flag 3). The module docstring names the posture inversion vs `ALLOWED_SFTP_HOSTS`: same normalize-then-compare shape, **opposite failure mode** — this filter must never raise and never narrow to zero (`test_unknown_email_enters_unfiltered`).
- **Config key:** `MappingConfig.district_domains: list[str] = []` — top-level next to `district_name` (`models.py:579`). `model_config = ConfigDict(extra="ignore")` is **declared explicitly** with a forward-compat rationale comment (today it holds only by Pydantic default while five sibling models declare `forbid`). A field validator pins each entry to a lowercase domain shape (`^[a-z0-9][a-z0-9.-]*\.[a-z]{2,}$`, no `@`) — a full email address pasted into the list fails `make validate-config` loudly, in CI, before it can ship. A one-line test asserts `to_raw_dict()` output is unchanged by the key's presence (top-level fields structurally cannot reach the ETL). Tests pin: the `myedbc` base never carries domains (a base domain would leak to **every descendant config**), and `sd51attendance` inherits SD51's list via `_base` (deliberate — the same-district tiers share the domain). **No config `version:` bump** — the loader's "bump MINOR on new features" docstring (`loader.py:43-49`) is amended to scope the gate to ETL-affecting keys, recorded as a dated DECISIONS entry (a bump would also be noise: half the bundled configs pin their own `version` and resolve to 1.0).
- **The values (ship in S3, no tool needed):** `sd40myedbc: [sd40.bc.ca]` · `sd48myedbc: [sd48.bc.ca]` · `sd51myedbc: [sd51.bc.ca]` (inherited by `sd51attendance`) · `sd54myedbc: [sd54.bc.ca]` · `sd60myedbc: [prn.bc.ca]` (the staff domain — NOT the student `learn60.ca`) · `sd74myedbc: [sd74.bc.ca]`. Authored directly in the YAMLs from the owner's verified-contacts sheet (the sheet itself never enters the repo); the base and `mbp_*` tiers carry no list (unclaimed). The pre-release owner gate is a review of these six lines.
- **Repo hygiene gate:** an email-shaped-regex scan joins the existing pre-commit hook and CI, over the **whole repo** (tracked files) with a short explicit allowlist (`help.py`'s `SUPPORT_EMAIL`, the `example.com/org/invalid` synthetics) — a future legitimate address is a visible allowlist line, never an invisible path hole; `.gitignore` gains `*allowlist*candidate*` / `*.emails`. Plan/spec/QA files are public surfaces under the same rule.
- **The launch page** mounts in `shell.main` between the geometry block and the app body. The refactor is honest about its size: the window-close lifecycle (`page.window.on_event` AND `page.on_disconnect` — the zero-orphan guarantees, today at `shell.py:417-434`) hoists ABOVE the gate; `page.add(root_host)` happens once, with the identity view and the app body swapped via `root_host.content` (the proven `content_host` pattern — no new 0.85.3 API); the app body extracts to a module-level `build_app_body(page, app_cfg)` (not a 110-line closure); the Setup badge probe stays after entry. Boot order is enumerated in the spec and pinned: close handlers bound while the page is up; `_enter_app` runs exactly once; closing at the identity page orphans nothing (title-bar close accepted — no rail, no Exit button, stated).
- **The page can never trap anyone:** `needs_identity(cfg)` (pure: not `settings_unreadable()`, not `has_completed_setup()`, no stored `identity_email`) + **a floor over the whole identity layer** — any exception in the predicate, the render, or resolution logs and falls through to the app body (`_enter_app()`), making "never fails closed" mechanical, pinned by a smoke that injects a raise into the identity build and asserts the shell mounts. **Persist best-effort, then enter — never trapped, never mis-scoped:** resolution attempts the wrapped persist FIRST (`SettingsOverwriteRefused`, `OSError` → log + continue; the gate re-asks next launch), then calls `_enter_app()` with a **fresh `AppConfig.load()`** so the first session's lists are correctly scoped from the first paint; a persist failure still enters (never a trap). The order joins the boot-order enumeration, and a first-paint test pins that the app body sees the persisted identity. All identity writes route through one `identity_save()` choke point that re-checks `settings_unreadable()` on the instance it is about to save (the guard lives on the WRITE, not the boot-time decision). Structurally: the new fields are all `identity_*`-prefixed and join an `_ADVISORY_FIELD_PREFIXES = ("window_", "identity_")` exclusion in `_carries_chosen_settings`, so an identity-only save on an unreadable profile is refused by the existing machinery.

### Filtering = one catalog-layer choke point with an unclaimed-config rule

- **The rule (two tiers, reconciled with flag 4 at R3):** (i) **No identity / no match / show-all → ALL configs**, unclaimed included — fail-open is the default state of the world. (ii) **Matched** (≥1 config's resolved non-empty `district_domains` contains your email's domain) → exactly the matching configs, PLUS the saved `sis_type` unconditionally. **Matching is exact, case-normalized domain equality — never subdomain/suffix/wildcard** (`mail.sd48.bc.ca` does NOT match `sd48.bc.ca`; a district needing a second domain or subdomain gets it as its own list row) — the safe direction under fail-open. The tri-state (`None` = degraded, `()` = declared-empty, non-empty = claimed) still matters: a degraded config can never *match* anyone, so a broken YAML can only ever widen a list (its own admin falls to tier (i) and sees everything), never hide the right district. A district *disappearing on its own admin* is the failure this rule makes unrepresentable.
- **Placement:** matching + the display rules live at the **catalog layer** (`mapping_catalog.filtered_catalog(domain, *, saved_sis, show_all, config_dir=None)` — the caller passes `extract_domain(normalize_email(email))`) — `identity.py` stays primitives-only; the plaintext email is confined to the identity/Settings screens + AppConfig. **Data source specified:** `ConfigSummary` gains `district_domains: tuple[str, ...] | None` resolved during the same single catalog build (no re-parse; the memoization survives) — `None` = unresolvable/degraded, `()` = declared-empty, and only a **non-empty** tuple can ever exclude (the unclaimed rule distinguishes all three). The docstring gains one line naming the new field (public organizational domains — no personal data; the module's no-student-PII contract is untouched). Layer note vs CLAUDE.md's UI/ETL isolation: the matching rule sits in this UI-layer module deliberately — it is presentation scoping (which rows a picker shows), it consumes config data the module already loads, and the ETL structurally cannot see the key (`to_raw_dict`). `saved_sis` is a signature parameter unconditionally included in the result — the escape is a property of the choke point for every caller that passes it (the three call sites each pass `app_config.sis_type`; a truth-table row pins it). Deterministic ordering pinned. Consumed by `setup._district_options()`, **`setup.py:350`'s auto-select seed (the previously-unnamed fourth consumer)**, `convert.build_convert`, and `mapping.build_mapping` — one catalog build per mount, passed down (mapping.py's current double `list_configs()` parse collapses to one), memoized per session so the launch path never re-parses 11 YAMLs per paint; any raise in catalog building degrades to unfiltered.
- **D9 interaction decided:** the wizard's District seed reads the same filtered list; `auto_selected_district` under a filtered one-entry list now auto-selects the matched district — aligned with D9's "auto-select only when exactly one option exists", now scoped to the *visible* list, correctable at the District step (which is a pre-selection surface by design). The stale DECISIONS L120 "unreachable branch" note is updated in the same slice.
- **Labels:** the sd51 collision dies via the one-line `district_name` (flag 10) — every `friendly_district_name` consumer (11 sites incl. the mismatch note, Run History's "Different district", Help, the support subject) inherits it. The picker-row builder disambiguates deterministically on any residual display-text collision (appends the sis id) — covering user-dir YAMLs we don't control; the G13 test pins the **bundled** catalog renders no two identical labels and is written first and observed RED on current main (the collision is real today).
- **Show-all:** a text-tier row at the foot of each filtered list, rendered whenever a shorter list EXISTS (keyed on `can_filter`, so it survives being switched ON — keying it on "narrowed right now" would strand the admin in the long list); wording "Show all districts — we're only showing yours to keep the list short"; when on, the row inverts to "Showing all districts · Show only mine". Per-SURFACE, re-scoped every mount (flag 5, as landed).
