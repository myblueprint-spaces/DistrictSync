## Problem

Four owner-approved gaps (Brief 0037, Phase 1):

1. **The exe ships ~100MB of Flutter client it doesn't need.** The `full` desktop flavor is embedded on Windows/macOS (`.github/workflows/flet-pack.yml:30,46`) though the app uses no audio/video; Linux already ships `light` (PLAT-0b). D-0037-1 flips Win/mac to `light` (~−13MB measured target). A standing decision (DECISIONS 2026-07-14) declined this pending "a green Win+mac UI smoke" — the pack-smoke at `flet-pack.yml:209-215` is exactly that smoke, so the flip carries its own evidence.
2. **The new-user front door is a door into a room you're standing in.** Unconfigured Home renders an onboarding hero whose CTA routes to the Setup rail item (`src/ui_flet/screens/home.py:285-290` → `onboarding.py`); the wizard lives one click away from where the user already is. D-0037-2: Home hosts the wizard itself. Post-setup, Home is a metric-tile dashboard (`home.py:207-209`) whose tiles duplicate what Run History shows and lose their counts on any imperfect run (ROADMAP L59); D-0037-3: slim Home = one verdict line + quick actions.
3. **The app doesn't know who it's talking to.** All 11 district configs are offered to every admin in three pickers (`setup.py:248-250`, `convert.py:589-595`, `mapping.py:265-273`); the highest-consequence wrong click in the product is picking the wrong district (a wrong mapping ships a wrong roster — student PII). Two of the eleven rows render byte-identically ("SD51 - Boundary School District" twice — `sd51attendance_mapping.yaml` inherits SD51's `district_name`). D-0037-4: a launch identity page resolves the admin's work email against per-district salted-hash allowlists baked in the bundled YAMLs and filters every district list; labels become distinguishable.
4. **The output contract lives nowhere.** No doc lists the emitted CSV columns; `tests/test_contract.py:35-57` asserts membership (not order), covers 5 of 8 entities, and asserts nothing about the per-entity BOM rule (`loader.py:53 _NO_BOM_ENTITIES`). Brief item 4: an in-repo `docs/developer/output-contract.md` (the MAINTAINED authority, confirmed against the live importer 2026-07-27) + strengthened tests.

Plus the P1 leftovers from the 2026-07-27 field-test analysis: the Convert header chip asserts the *saved* district while the run uses the *picked* one (`convert.py:1166-1173`, comment admits it); no CI job runs the built exe's CLI branch at all; QA-checklist and product-spec rows for every new surface.

## Goals / Non-goals

- **Goal:** land Phase 1 as a sequence of complete PR slices to `main` (D-0037-6: one release, tagged only after Phase 2 + certification).
- **Goal:** every UI slice upholds the Direction B design system (build via `components.py`, tokens-only, one filled primary, verdict-first, AA-gated pairs) and the PII bar (the identity email never reaches a log, a run record, or non-Settings copy).
- **Goal:** an existing configured install upgrades onto slim Home with a one-time, non-blocking identity prompt — never back into the wizard, never a launch gate (D4a preserved).
- **Non-goal:** the mapping creator (Phase 2, D-0037-5). The "my district isn't listed" path lands as a support-mail card, replaced by "Build my mapping" in Phase 2.
- **Non-goal:** failure notifications (D-0037-7, deferred release+1).
- **Non-goal:** authentication or access control. The identity page is UX filtering; all mappings still ship in the exe; the copy never claims otherwise (banned vocabulary: sign in / log in / verify / unlock / authorized / account / credentials / access).
- **Non-goal:** real allowlist VALUES. Hash lists ship EMPTY in every YAML until the pre-release owner approval of the final rows (brief: "per-row owner confirmation happens at pre-release"); the hashing tool + schema land now. Empty lists → no match → unfiltered entry (fail-open), so every intermediate build behaves like today.
- **Non-goal:** changing the CLI. `src/main.py::_cli` (scheduled runs, `--sftp-*`, `--dry-run`, cron) is untouched by identity (G1 — the batch's #1 non-regression invariant).

## Approach

**Identity = one new pure module + one additive config key + one in-shell gate.**
- `src/utils/identity.py` (new, COUNTED): `normalize_email` (lowercase/trim), `hash_email` (SHA-256 over `SALT + normalized`), `match_districts(email_hash, catalog) -> list[str]` (configs whose resolved `authorized_email_hashes` contain the hash), `districts_for_display(match, *, show_all) -> list[str]` (match + `myedbc`; no match/show-all → all), `sd_number_candidates(text, catalog)` (filename-prefix `sd{N}` match). Salt = committed constant with an honest docstring.
- `MappingConfig.authorized_email_hashes: list[str] = []` — top-level next to `district_name` (`models.py:579`), NOT in `global_config` (whose `to_raw_dict()` whitelist would drop it; the value has no business reaching the ETL). Pydantic `extra="ignore"` means every shipped build already tolerates the key: additive, no config-version bump. `_base` inheritance does the district-keying for free (`sd51attendance` inherits SD51's list); hashes are NEVER placed on the `myedbc` base (they would leak to all nine children). The owner's own hash is added per-district by the pre-release script.
- `scripts/hash_allowlist.py` (new): owner-run at pre-release; reads a LOCAL plaintext candidates file (path argument — never committed), emits `authorized_email_hashes:` YAML blocks per district. The repo stays email-free.
- The gate mounts in `shell.main` between the geometry block and the nav model (`shell.py:270→271`): the post-geometry half refactors into an `_enter_app()` closure; when `show_identity_gate(cfg)` (new pure predicate: not `settings_unreadable()`, not `has_completed_setup()`, no stored `identity_email`) the shell renders the identity surface instead, and resolution persists + calls `_enter_app()`. Window-close handlers bind BEFORE the gate; the Setup badge probe stays AFTER it. Alternatives rejected: a screen-map entry (rail visible/clickable behind it — not a gate), a second `ft.run` (unproven on 0.85.3; first window's `on_disconnect → os._exit(0)` kills the process), a modal dialog (paints the shell behind it).
- Existing configured installs (`has_completed_setup()` true) never see the gate: a dismissible identity card on slim Home, below the verdict band, persisting `identity_email` or `identity_prompt_dismissed`; permanently editable at Settings → "Who looks after this sync".

**Filtering = one choke point + a display-label fix.**
- All three pickers converge on `loader.available_configs()` (raw ids, no parse). The filter applies where configs are already loaded: a new pure `filtered_catalog(identity_email, *, show_all, config_dir)` beside `mapping_catalog.list_configs()`, consumed by `setup._district_options()`, `convert.build_convert`, and `mapping.build_mapping`. The saved `cfg.sis_type` is ALWAYS included (mapping.py:137-142's `setdefault` escape generalized) so a filtered list can never hide the running config or kill Convert's prefill (`convert.py:547`).
- Labels: new additive `MappingConfig.variant_label: str = ""`; display = `district_name` (+ ` · {variant_label}` when set). `sd51attendance` gets `variant_label: "Attendance"`. A test pins that no two catalog entries render identical display text (G13). Phase 2's creator reuses the field.
- "Show all districts" = a text-tier row at the foot of each filtered list + a persistent Settings toggle (`district_list_show_all`), worded as list scope ("we're only showing yours to keep the list short"), never as an unlock.

**Home restructure = a host seam + a subtraction.**
- Wizard-on-Home: `build_setup` gains `on_complete: Callable[[], None] | None` (fired at `_finish` instead of mutating its own root into Settings — `setup.py:442-448`); Home's branch (a) hosts `build_setup(page, on_complete=..., on_schedule_changed=...)` inside the same try/except→`ErrorCard` as branch (b/c); the shell forwards `_on_schedule_changed` to Home (`shell.py:301-306`); the wizard session dict `ws` hoists to a module-level session so a Home↔Setup hop doesn't fork state (G9c) and resets on completion; `nav._INITIAL_WHEN_SETUP_NEEDED` retires (launch selection = Home always); the onboarding hero collapses to a one-line welcome band above the wizard (gradient allowance moves to the identity page); no Setup attention badge during first-run.
- Slim Home: `_dashboard` drops the tile row + section label (`home.py:207-209`); quick actions = ONE filled primary + outlined tier per the fault/healthy rule (fault → fix-CTA filled + three outlined; healthy → "Convert now" filled + Run History/Settings outlined); the schedule row-card STAYS (it answers "will it run again?", not a metric); the healthy detail carries one roster-size number ("Last sync delivered N students…") to keep size-plausibility (G10c); the finishing session renders the honest finish summary on Home, reverting to the slim verdict on next mount. Copy single-sourcing: the headline/detail strings `run_history.py` re-phrases are hoisted into `home_status` shared providers so Home and the Run History banner render the same words for the same state (D-0037-3's "can never disagree" made true at the copy layer, not just classification).

**Contract = a doc + assertion strengthening, no data change.**
- `docs/developer/output-contract.md`: per-entity column tables (already universal — no district overrides set/order; the merge rule at `loader.py:139-155` guarantees it), semantics, the BOM matrix (`utf-8-sig` everywhere except `StudentAttendance` plain UTF-8, with the verbatim loader rationale), CRLF/RFC-4180, the attendance category vocabulary + ISO date default with the live-importer-wins reconciliation verdicts, the tier table (which configs emit which CSVs), format authorities per brief (rostering → the Google Doc as published reference, the doc itself as maintained authority stamped 2026-07-27; attendance → the two attendance Docs; CourseInfo/StudentCourses → "internal spec" citing the Confluence pages). Inbound links from `architecture.md` (whose stale Output-tiers/Loader sections get corrected) and `release.md:168,183`.
- `test_contract.py`: set assertions → ORDER equality (the schema lists are already in field_map key order); per-entity BOM assertions on the written files; CourseInfo (13)/StudentCourses (10)/StudentAttendance (4) schemas added with runs of `mbponly` + `sd51attendance` wired into the existing module-scoped fixture pattern.

**CI exe smokes = new steps in the one builder.**
- Three new steps in `flet-pack.yml` after the pack step, reusing `scripts/ci_flet_pack_smoke.py` helpers (`resolve_artifact`, `etl_log_candidates`, `_phase_close`): (1) `--version` redirected to a file, assert exit 0 + `DistrictSync ` prefix; (2) `--sis sd74myedbc --input tests/snapshots/input --output <tmp> --dry-run`, assert exit 0 + the `=== DRY RUN` banner + the five entity names (NOT row counts — the golden regression owns values); (3) stale-profile boot: corrupt `config.json` planted via `LOCALAPPDATA`/`XDG_DATA_HOME` override, CLI-branch `--version` asserts exit 0 (no crash, no re-onboard). Widen `flet-verify.yml`'s path filter with `config/mappings/**` + `src/config/**` so config PRs build an exe.
- The light-flavor flip is then two matrix values (`flet-pack.yml:30,46`) + the comment + Makefile `FLET_DESKTOP_FLAVOR` parity + doc updates (`FLET_1.0_CONVENTIONS.md:121-137`) + a dated DECISIONS reversal citing the green light-flavor smoke run as the evidence the 2026-07-14 decline demanded.

**Convert pill = a pure sibling helper + a header refresh.**
- `convert_output.this_run_label(selected, saved, *, config_dir)` beside `district_mismatch_note` (`convert_output.py:141-158`); rendered as `status_pill("This run: <name>", Verdict.WARNING)` + a `text_button("Change mapping", on_navigate("mapping"))` in the header's trailing Row (the `home.py:63-88` multi-control precedent); `_refresh_header()` joins `_on_district_change`'s call list. NOT threaded into `can_run_convert` (the explicit-pick-is-sufficient contract and its 5 gate tests stay).

## Architecture & holistic fit

- **Codebase fit.** Every new decision lives in a pure COUNTED module mirroring the established spine: `identity.py` beside `validators.py` (the normalize-then-compare allowlist shape of `ALLOWED_SFTP_HOSTS`); `filtered_catalog` beside `mapping_catalog.list_configs` (the one place configs are already loaded); the gate predicate beside `nav.needs_setup` (THE-predicate pattern); `this_run_label` beside `district_mismatch_note`. View glue stays coverage-omitted and assembles via `components.py` factories only. The config schema change is additive on a model that ignores unknown keys — old builds load new YAMLs, new builds load old ones. The shell refactor (`_enter_app()` closure) preserves the existing boot order contract (close handlers before gate, probes after).
- **Product fit.** `docs/claugentic-PRODUCT.md` (updated by the Stage-1 Discover pass) now carries the durable rules this plan implements: identification-never-authentication (+ banned vocabulary), no-two-options-read-identically, the front door's four honesty rules (never withholds, never fails closed, never touches the network, never gates work), Journey 4 (upgrade-in-place as a non-regression guarantee). Slim Home is the verdict-first spine taken to its conclusion.
- **Quality dimensions to uphold** (→ Spec refines per slice): `product-ux` (flows/states/copy on every touched surface) · `security` (allowlist honesty, salt threat model, user-mappings-dir precedence, no new secrets) · `maintainability-structure` (choke points, no respelled predicates) · `testing` (contract order/BOM pins, exe smokes, render smokes, pure-module truth tables) · `data-and-persistence` (AppConfig additive fields, atomic saves, UNREADABLE guard) · `api-and-contracts` (the output contract doc + config-schema additivity) · `reliability-resilience` (fail-open gate, never-crash floors) · `observability-ops` (identity never in logs/run records) · `docs-traceability` (contract doc, QA rows, DECISIONS reversals).
- **Future-proofing.** `variant_label` + the hashing script are the Phase-2 creator's inputs (a user-made mapping needs a label and, later, an allowlist row). The filter choke point takes the catalog as data, so a future served/updatable registry swaps the source without touching consumers. Nothing speculative is built (no registry, no notification transport, no editor).

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Light flavor breaks rendering on Win/mac | The flip PR's own CI run executes the pack smoke (real window, WM_CLOSE, orphan check) on the light client across all 3 OSes; red = don't merge; rollback = revert two matrix lines. Local `make build-win` gets the same env var so dev boxes match CI. |
| Identity gate regresses the nightly sync | G1: no CLI change at all; the gate exists only in `shell.main`. Existing pinned CLI tests + the new `--dry-run` exe smoke stand guard. |
| Identity save corrupts an UNREADABLE profile | G2: `show_identity_gate` and the Home prompt both require `not settings_unreadable()`; no third single-field-save caller is added on the launch path. |
| Filtered list hides the running config | The saved `sis_type` is unconditionally included (generalized `setdefault` escape); Convert's prefill membership test (`convert.py:547`) runs against the escaped list. |
| Email leaks into logs/records/copy | The PII bar extends: a static test asserts `identity_email` never appears in `__DISTRICTSYNC_RUN__` construction, the run store schema, or `humanize`/`home_status`/`run_history` copy paths; only Settings/Help render it. |
| Two wizard hosts fork state | `ws` hoists to a module-level session (reset on completion + on profile change); resume already derives from real state, so a stale session reconciles. Both hosts graduate off the same `has_completed_setup()`. |
| Home render smokes churn | `test_home` (unconfigured) newly exercises the wizard build path — the smoke harness's autouse `AppConfig.load` patch + the stubbable `_kick_probe_thread` seam already support it; assertions updated deliberately (verdict-first index test, wizard-finish assertions inverting under the Home host). |
| Order pin fights a future district override | No override exists today and the doc states the rule ("districts change sources, never the output shape"); a future exception would fail the contract test loudly — the desired behaviour. |
| A user-dropped YAML in the app-data `mappings/` dir carries attacker-chosen hashes | Named honestly in the contract: local FS access already reads every config and the identity layer is UX filtering, not a security boundary (D-0037-4's honesty bar); no claim of protection is made anywhere in copy or docs. |
| The wizard-finish moment regresses (amber "fresh start" replacing the payoff) | The finishing session renders the finish summary on Home (G10d); the render smoke pins it. |
